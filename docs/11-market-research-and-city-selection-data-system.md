# 市场研究与城市选择数据化体系

> 状态：建议方案，待首发城市、数据来源和权重评审。本文定义如何用数据评估城市、验证供需、管理试点并决定扩张，不预设未经调研的城市排名或市场规模。

## 1. 建设目标

建立持续更新的市场决策体系，回答：
- 哪个城市适合启动住宅水电安装服务交易？
- 哪些区县/商圈具备足够的供需密度？
- 当前短板是需求不足、服务商不足、报价响应慢，还是履约质量差？
- 应该增加获客、招募服务商，还是优化交易转化？
- 何时可以复制到下一个城市？

城市选择不是一次性打分。应由公开统计数据、平台调研数据、真实交易数据和运营成本数据共同驱动，并记录数据来源、采集时间、口径、可信度和责任人。

## 2. 数据分层

### A. 城市基础数据（外部数据）
- 常住人口、家庭户数、人口流入与年龄结构。
- 城镇化率、住宅存量、住宅竣工/交付情况。
- 房地产交易、二手房流通和装修相关公开指标。
- 城市GDP、居民收入、消费水平。
- 行政区划、交通时间、区域面积。
- 建筑业企业、建筑业从业人员等可获得的公开统计数据。

来源优先级：
1. 国家统计局及地方统计局公开数据。
2. 住建、市场监管、人社等政府部门公开信息。
3. 政府统计年鉴、统计公报和公开行业报告。
4. 合法授权的商业数据服务。
5. 一手访谈与抽样调查。

不得把搜索引擎结果数量、地图商户数量或未经验证的行业报告直接当作真实市场规模。

### B. 供给侧数据（调研与平台数据）
- 可联系施工人员数量。
- 可核验的个体经营者、施工企业数量。
- 服务品类、技能、经验和可服务区域。
- 可承接工单量、排期、响应时间。
- 资质/许可适用情况及核验状态。
- 报价响应率、接单率、取消率。
- 服务商获客渠道、参与意愿及收费接受度。

### C. 需求侧数据（调研与平台数据）
- 业主有效需求量及来源渠道。
- 需求类型：新房安装、旧房改造、局部维修等。
- 预算区间、期望开工时间、服务半径。
- 有效需求率、报价覆盖率、签约率。
- 需求方对平台保障、合同、验收和售后的关注程度。
- 需求季节性与区域差异。

### D. 交易与履约数据（平台真实数据）
- 需求发布、审核通过、报价、签约、开工、完工各阶段数量。
- 阶段转化率和阶段耗时。
- 客单价、报价离散度、订单金额分布。
- 按时履约率、验收通过率、返工率。
- 取消、退款、投诉、争议率。
- 复购率、转介绍率和服务商留存率。

### E. 经营成本数据
- 需求获客成本（按渠道拆分）。
- 服务商招募与审核成本。
- 城市运营人员、客服和质检成本。
- 支付机构费用、短信/地图/存储等可变成本。
- 退款、赔付、争议处理和售后成本。
- 城市启动的一次性成本与持续固定成本。

## 3. 城市评估指标体系

先使用指标面板，不立即把所有指标压成一个分数。

| 维度 | 核心指标 | 解释 |
|---|---|---|
| 需求潜力 | 目标住宅家庭规模、住宅交易/交付活跃度、访谈有效需求率 | 判断潜在需求基础 |
| 供给基础 | 可核验服务商数、品类覆盖、可用产能 | 判断能否承接 |
| 供需匹配 | 有效需求/可用服务商产能、报价覆盖率、响应时长 | 判断市场流动性 |
| 交易可行性 | 签约率、完工率、客单价、复购/转介绍 | 判断能否形成闭环 |
| 履约质量 | 按时率、验收通过率、返工率、投诉率 | 判断服务质量 |
| 获客效率 | 有效需求CAC、服务商招募成本、渠道转化率 | 判断增长成本 |
| 经营效率 | 单笔贡献毛利、城市固定成本、盈亏平衡订单量 | 判断商业可持续性 |
| 合规可行性 | 主体核验完成率、必要资质核验率、支付路径可用性 | 判断能否合法经营 |

每个指标必须有：
- 明确定义和计算公式。
- 统计范围、时间窗口和去重规则。
- 数据来源与更新时间。
- 样本量、缺失率和可信度等级。
- 责任人及异常解释。

## 4. 城市评分模型（建议初始权重）

只有在数据完整性达到门槛后才计算综合评分。建议先采用以下权重作为讨论起点，而非客观真理：

| 维度 | 建议权重 |
|---|---:|
| 需求潜力 | 20% |
| 供给基础 | 20% |
| 供需匹配 | 15% |
| 交易可行性 | 15% |
| 履约质量 | 10% |
| 获客效率 | 10% |
| 经营效率 | 5% |
| 合规可行性 | 5% |

评分规则：
- 定量指标优先按同一口径归一化，避免人口规模等单一大指标支配结果。
- 定性指标采用明确的分档标准，并保留评分证据。
- 缺失数据不得自动按满分或零分处理；标注缺失并降低评分置信度。
- 对数据量不足的城市显示“样本不足”，不输出伪精确排名。
- 合规硬门槛不应被高商业得分抵消；关键经营主体或支付路径未核验通过时，不进入真实交易上线。
- 同时展示总分、分项分、数据完整度、置信等级和风险项。

## 5. 试点城市验证实验

### 第一步：桌面研究
针对候选城市收集人口、住宅、收入、产业、交通和公开行业数据，记录原始来源及年份。

### 第二步：供需访谈
每个候选城市采用统一访谈提纲，覆盖：
- 住宅业主/房屋持有人。
- 独立施工人员及个体经营者。
- 小型施工企业。
- 物业、装修公司或其他需求入口。
- 材料商及相关产业服务商。

访谈样本数量由研究预算和城市规模确定，不能把便利抽样结果宣称为全市代表性统计。

### 第三步：人工撮合试验
在产品功能尚未完善时，以合规方式人工协助真实需求与服务商匹配。每条需求记录：
- 来源渠道及获客成本。
- 区域、品类、预算、工期。
- 邀请服务商数、有效报价数、响应时间。
- 是否签约、未成交原因。
- 是否开工、是否完工、验收和售后情况。
- 平台投入的人工时间和实际成本。

不得以虚构订单、模拟成交或意向问卷替代真实交易验证。

### 第四步：复盘与决策
按周查看供需漏斗和异常订单；按月评估城市的交易密度、履约质量和贡献毛利。城市扩张决策必须附原始数据窗口、样本量和风险说明。

## 6. 城市经营看板

建议首期运营看板包含：

### 市场概览
- 城市/区县覆盖范围。
- 有效需求数、活跃服务商数。
- 需求与服务商增长趋势。
- 品类和区域分布。

### 供需匹配
- 待匹配需求数。
- 平均有效报价数。
- 首次响应时间中位数及P90。
- 无报价需求占比。
- 服务商可用产能与排期。

### 交易漏斗
- 发布 → 审核通过 → 获得报价 → 选定服务商 → 签约 → 开工 → 完工。
- 各阶段转化率、流失原因和平均耗时。

### 履约质量
- 按时开工率、按时完工率。
- 验收一次通过率、返工率。
- 取消、退款、投诉和争议情况。

### 单位经济
- 分渠道有效需求CAC。
- 单笔平台收入。
- 单笔变动成本和贡献毛利。
- 城市固定成本及盈亏平衡订单量。

### 数据质量
- 指标更新时间。
- 样本量和缺失率。
- 来源可信度。
- 数据异常和人工修订记录。

## 7. 城市扩张门槛

城市扩张不使用单一GMV或用户数作为条件。建议同时满足：

1. 连续多个完整观察周期存在稳定有效需求。
2. 主要服务品类拥有足够且可核验的服务商供给。
3. 需求获得报价的覆盖率和响应速度达到项目设定目标。
4. 签约、完工、验收和售后指标稳定。
5. 单笔贡献毛利和城市经营模型具备改善或可持续路径。
6. 投诉、安全和合规风险处于可管理范围。
7. 新城市已有本地运营负责人、服务商招募渠道和客服处置能力。

具体阈值须通过首发城市真实试点数据制定，不在缺乏样本时编造统一行业基准。

## 8. 数据治理与隐私

- 只收集实现业务目的所必要的数据。
- 对个人身份、联系方式、住址、施工现场图片等敏感信息设置访问权限和保存期限。
- 研究分析优先使用去标识化、聚合后的数据。
- 外部数据遵守授权、来源和使用范围限制。
- 记录数据采集时间、口径变化、修订人和修订原因。
- 公开统计数据、第三方商业数据、访谈数据和平台交易数据分层保存，不混淆来源。
- 不因城市评分或算法结果自动作出对服务商不利的重大决定，应提供人工复核渠道。

## 9. 建议的数据产品演进

| 阶段 | 数据能力 |
|---|---|
| 研究准备 | 城市指标字典、来源登记、访谈记录模板 |
| MVP | 需求/服务商/报价/交易漏斗、人工运营报表 |
| 单城稳定 | 区域热度、供需匹配、渠道CAC、履约质量 |
| 多城运营 | 城市对比、城市健康度、扩张门槛、预算追踪 |
| 全国规模 | 统一指标平台、数据质量监控、预测分析和实验评估 |

首期无需建设庞大数据仓库。先把关键业务事件和指标口径设计正确，使用关系型数据库和定期报表即可；当数据量、分析复杂度和组织需求增长后再建设独立分析平台。

## 10. 当前待确认事项

- 首发候选城市名单。
- 首批住宅服务品类。
- 城市评分权重是否接受。
- 研究预算、调研周期和样本设计。
- 供需访谈和人工撮合试验的执行人。
- 城市扩张的观察周期和具体阈值。

**结论：** 城市选择应当是持续更新的数据决策过程，而不是一次性的城市排名。先建立数据口径与真实样本，再形成评分；先验证单城交易密度与履约质量，再复制城市模型。
