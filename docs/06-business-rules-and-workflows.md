# 业务规则与流程设计

> 文档状态：讨论稿 / v0.1  
> 更新时间：2026-11-20  
> 适用范围：中国大陆水电安装服务与工程交易平台  
> 上游文档：01 商业定位、02 商业模式与法律主体关系、03 交易模型、04 支付与结算合规、05 产品架构  
> 本文目标：定义住宅水电安装交易的业务规则、角色权限、状态流转、异常处理和运营介入边界；不在本阶段设计数据库表或具体代码。

## 1. 业务规则总原则

1. **真实主体：** 每笔交易明确需求方、服务提供方、合同签约方、实际履约方和收款权利主体。角色可以重合，也可能不同，但必须有依据。
2. **合同优先：** 服务范围、材料约定、工期、付款条件和售后责任以双方确认的合同及有效变更文件为准。
3. **双向确认：** 涉及价格、范围、工期、验收和退款等重要权益的事项，不能由单方静默修改。
4. **过程留痕：** 需求、报价、合同、施工记录、变更、验收、支付通知、退款和投诉均保留时间、操作主体及证据。
5. **状态分离：** 需求、报价、合同、履约、验收、支付和售后状态分别管理。
6. **平台职责边界：** 平台可以执行规则、提供证据和组织协商，但不得把平台规则包装成法定工程验收、质量鉴定或司法裁判。
7. **风险优先：** 涉及人身安全、重大质量隐患、违法施工线索、资质异常和资金异常时，优先暂停相关流程并启动人工核查。
8. **规则透明：** 平台服务费、派单规则、排序规则、取消规则、投诉流程和处罚规则应适当公示并留存版本。

## 2. 交易主体与权限

### 2.1 交易参与角色

| 角色 | 可以执行 | 不得默认拥有 |
|---|---|---|
| 需求发布人/业主 | 发布需求、查看报价、确认合同、确认变更、验收、发起售后 | 代表其他共有人或单位签约的权限 |
| 服务商负责人 | 管理服务资料、组织报价和履约 | 超出经营主体授权的签约权 |
| 报价人 | 提交和修改有效期内的报价 | 代表其他企业签约的权限 |
| 合同签署人 | 按授权签署合同 | 修改未授权的合同主体或收款主体 |
| 项目/现场负责人 | 预约、施工记录、提交变更和验收申请 | 单方面变更合同价款或代替业主验收 |
| 实际施工人员 | 查看被分配任务、提交施工记录 | 自动取得合同签约权、收款权或平台员工身份 |
| 平台客服/运营 | 审核、提醒、组织沟通、处理平台规则事项 | 代替交易双方确认合同、工程量或验收 |
| 平台风控/合规人员 | 暂停风险流程、核验资料、记录处理结论 | 绕过支付机构直接划转交易资金 |

### 2.2 权限校验

每个关键动作至少校验：
- 当前登录用户身份有效。
- 用户与交易之间存在有效参与关系。
- 以组织身份操作时，具有有效成员关系及相应权限。
- 操作对象处于允许该动作的状态。
- 涉及合同、付款、退款或验收时，操作者具备相应授权。
- 高风险操作要求二次确认或人工复核。

组织成员离职、权限撤销或组织主体变更，不应抹去历史操作记录；应保留操作发生时的身份和授权快照。

## 3. 服务类目与需求发布

### 3.1 首期服务分类

建议首期分为新房水电安装、局部水电改造、水路维修、电路维修、卫浴/厨房相关水电安装，以及其他经平台审核开放的住宅水电服务。

每个服务类目配置适用范围、需求采集字段、服务商准入条件、风险提示和验收参考项。不能只用一个“水电安装”类目覆盖所有不同施工风险。

### 3.2 需求信息

根据服务类型动态要求：
- 需求联系人及其对房屋/项目的关系。
- 服务所在城市、区县及必要的上门地址信息。
- 房屋类型和施工场景。
- 服务内容、现场问题和期望结果。
- 面积、点位、长度、数量等可获得的工程量信息。
- 期望进场时间和可施工时段。
- 预算区间（可选）。
- 现场照片、视频、图纸或其他附件。
- 是否涉及拆改、隐蔽工程、高空、带电、燃气、消防或其他特殊风险。

平台应提示用户不要在公开需求中填写身份证号、门锁密码、银行卡信息等不必要的敏感信息。精确地址仅向履约所需且有权限的参与方展示。

### 3.3 需求审核

需求提交后依次进行字段完整性、地址与服务区域、服务类目开放状态、内容安全、异常信息、服务范围和特殊风险检查。通过后进入撮合；需要补充资料的退回补充；涉嫌违法或存在明显安全风险的转人工核查。

平台不得仅凭自动审核结果认定现场施工方案安全或工程合法。

### 3.4 需求状态

| 状态 | 含义 | 可执行动作 |
|---|---|---|
| DRAFT | 草稿 | 编辑、删除 |
| SUBMITTED | 已提交 | 等待校验/审核 |
| NEEDS_INFO | 待补充 | 发布人补充资料 |
| APPROVED | 审核通过 | 开始撮合 |
| MATCHING | 撮合中 | 邀请服务商、接收报价 |
| PAUSED | 暂停 | 申请暂停或平台风险暂停 |
| CONTRACTED | 已形成合同 | 进入订单履约 |
| CLOSED | 已关闭 | 查看记录、按规则申诉 |

需求关闭不等于已签合同自动解除；已有合同必须按合同取消或解除流程处理。

## 4. 服务商准入与接单

### 4.1 入驻资料分层

平台分别采集和核验：
- 自然人身份信息。
- 经营主体类型：自然人、个体工商户、企业或其他依法可经营主体。
- 主体登记信息及实际经营者信息（适用时）。
- 服务区域和服务类目。
- 技能、经验、培训或职业能力材料（作为能力信息，不自动等同法定资质）。
- 依法需要的许可、资质或特定岗位资格（按具体服务范围判断）。
- 联系方式、投诉联系人和售后响应方式。
- 收款商户进件状态（由合作银行/持牌支付机构按其规则核验，平台不得自行宣称已完成支付机构审核）。

### 4.2 准入状态

| 状态 | 含义 |
|---|---|
| DRAFT | 资料未提交 |
| PENDING_REVIEW | 待平台核验 |
| NEEDS_CORRECTION | 资料需补正 |
| VERIFIED_LIMITED | 在限定服务范围内通过核验 |
| ACTIVE | 可在已开放类目和区域内接单 |
| SUSPENDED | 暂停接单，待核查或整改 |
| REJECTED | 未通过准入 |
| WITHDRAWN | 主动退出平台 |

“通过平台审核”只表示完成平台规则要求的审核，不得表述为政府认证、工程质量保证或对所有施工项目具备法定承包资格。

### 4.3 接单限制

服务商只能在已开放服务区域和审核类目内报价；主体状态、授权状态和必要证照有效时承接相应服务；并按规则披露实际履约主体和可能参与施工的人员。

以下情况阻断新报价或接单：主体资料过期或重大变更未核验；依法需要的许可/资质缺失、失效或范围不匹配；支付机构商户状态不符合拟采用产品要求；账号被暂停或处于重大风险调查；服务商超出合理履约能力。

## 5. 撮合与报价

### 5.1 撮合方式

- **自主撮合：** 业主发布需求，符合条件的服务商查看并主动报价。
- **平台辅助推荐/派单：** 平台依据区域、服务类目、可用时间、服务商状态和历史履约指标推荐或邀请服务商。
- **定向邀请：** 业主或平台邀请指定服务商报价，服务商可接受、拒绝或在期限内提交报价。

平台应披露派单/推荐的主要规则和收费项目；不得使用虚假订单或虚假竞争报价制造稀缺感。

### 5.2 报价内容

报价至少包括报价主体、实际履约主体、服务范围及不包含事项、人工/材料/设备计价口径、工程量和总价、材料品牌型号规格及替代条件、预计工期、进场条件、有效期、付款节点建议、质保售后承诺、现场勘查要求及风险待确认事项。

不得只展示总价而隐藏重要排除项、材料规格或额外收费条件。

### 5.3 报价版本

- 每次提交生成独立报价版本。
- 业主接受前，服务商可撤回或提交新版本，但必须保留旧版本。
- 业主接受某版本后，该版本成为合同确认依据。
- 已接受报价不得被单方覆盖。
- 后续工程量或材料变化走合同变更，不得伪装成更新报价。
- 报价有效期届满后不可直接接受，服务商需重新确认。

### 5.4 报价选择与状态

业主可根据价格、范围、工期、服务商资料、历史履约和售后条件自主选择。平台可以提供排序和风险提示，但应避免将付费排名包装成客观质量排名。平台不应默认最低价中标；明显低于合理成本或范围不清时应提示核实。

报价状态：DRAFT → SUBMITTED → UNDER_REVIEW（如需审核）→ ACCEPTED / REJECTED / WITHDRAWN / EXPIRED。

## 6. 现场勘查与合同签署

### 6.1 现场勘查

当资料不足以准确估价时，服务商可提出现场勘查。双方确认时间、是否收费及收费标准；勘查结果形成现场情况、工程量估算、限制条件和待确认事项记录。勘查记录不自动构成施工合同或最终工程量确认，除非双方明确约定。

### 6.2 合同主体校验

签约前必须显示并确认需求方签约主体、服务提供方签约主体、实际履约主体、合同价款收款权利主体、平台在该交易中的身份，以及授权代表和授权依据。

合同主体与支付商户、开票主体不一致时，应阻断自动支付流程并转人工核验，不得隐藏差异。

### 6.3 合同核心条款

合同确认页至少覆盖服务内容和地点、工程量清单或计价方式、材料规格和替代机制、开工条件和工期、合同价款和付款节点、施工安全和双方配合义务、变更机制、验收依据和整改期限、售后/保修责任、取消解除和违约处理、发票税费约定、合同附件和版本。

平台合同模板不替代律师审查；复杂工程、特殊施工范围或高额交易应提示双方采用专业合同文本并进行必要法律审查。

### 6.4 合同确认

双方分别确认同一合同版本，记录确认人、确认时间、版本摘要和必要身份验证信息。条款变更生成新版本或正式变更文件。平台保存合同及证据，并提供双方可查阅的副本。

## 7. 订单创建与预约进场

合同达到约定生效条件后创建服务订单，关联需求、报价版本、合同版本、签约主体、实际履约主体和付款计划。

预约由服务商提出可进场时间，业主确认或调整；双方确认进场日期、现场联系人、施工时间和进场条件。预约变更应通知相关参与方并记录原因。现场无法施工或出现安全隐患时，服务商应记录事实并发起协调，不能自行认定业主违约。

订单状态建议：

| 状态 | 含义 |
|---|---|
| CREATED | 合同生效后创建 |
| AWAITING_SCHEDULE | 待预约 |
| SCHEDULED | 已预约 |
| READY_TO_START | 进场条件已确认 |
| IN_PROGRESS | 施工中 |
| CHANGE_PENDING | 存在待确认变更 |
| ACCEPTANCE_PENDING | 待验收 |
| RECTIFICATION | 整改中 |
| COMPLETED | 按业务规则完成 |
| CANCEL_REQUESTED | 取消申请中 |
| CANCELLED | 已取消 |
| DISPUTED | 争议处理中 |
| CLOSED | 订单归档 |

订单状态不应包含支付成功或已结算等资金结果；资金状态独立记录。

## 8. 施工过程管理

### 8.1 施工记录

服务商按订单要求记录进场/离场时间、施工阶段和完成内容、关键工序影像、使用材料及规格数量、隐蔽工程前后影像、现场问题和待确认事项、施工人员及现场负责人、安全隐患和停工原因、业主确认或沟通记录。

记录尽量在事件发生时提交；补录必须标记补录并保留原始创建时间和补录时间。上传照片不自动代表质量合格。

### 8.2 安全异常

发现疑似触电、漏水、燃气风险、结构安全问题、火灾风险或其他紧急危险时，应停止相关危险作业并采取合理避险措施；必要时联系当地应急、消防、供电、供水或专业机构；通知业主和现场负责人；记录现场情况。未经具备相应能力的人员确认，不得擅自恢复高风险作业。

平台提示不能替代现场安全管理、法定职责或专业技术判断。

### 8.3 隐蔽工程

对将被覆盖、封闭或后续难以检查的内容，设置施工前确认、施工过程记录、隐蔽前影像及必要检测资料、业主或授权代表确认和资料归档节点。业主未及时到场时，应按合同约定处理通知、见证和后续验收，不得默认沉默即认可所有质量事项。

## 9. 施工变更

### 9.1 变更触发

现场条件与原需求重大差异；业主新增或删除项目；材料规格替换；工程量变化；施工方案变化影响价格、工期或质量责任；发现原报价未包含但完成工程所必需的工作。

### 9.2 变更单内容

变更原因和现场证据、变更前后工作范围、工程量和价款增减、材料替换信息、工期变化、质量安全和售后责任影响、生效时间及双方确认。

### 9.3 变更规则

服务商或业主可发起变更申请。另一方确认前，变更不得作为新增收费或缩减服务范围的依据。紧急安全处置可先采取必要措施，但应及时通知并留证；费用和责任按法律、合同及事实确定。双方确认后形成新的合同变更版本。变更金额影响付款计划时同步更新业务计划，但不能改写外部支付交易。争议部分单独标记；无争议部分能安全、合法继续履行时，可按合同继续。

## 10. 验收与整改

### 10.1 验收依据

以合同、有效变更文件、适用强制性标准和双方约定的具体验收要求为依据。平台可以提供类目化检查清单，但不能声称通用清单覆盖全部工程规范。依法要求检测、专业验收或第三方鉴定时，应由具备相应资格或能力的主体完成。

### 10.2 验收流程

1. 服务商提交验收申请和施工资料。
2. 平台通知业主在约定期限内安排验收。
3. 业主选择验收通过、提出具体整改项或发起争议。
4. 整改项描述位置、问题、证据和期望处理方式。
5. 服务商回复整改方案并在约定期限内完成。
6. 业主复验并确认结果。
7. 存在分歧时进入协商、专业检测或争议处理流程。

验收状态：NOT_READY → SUBMITTED → INSPECTING → ACCEPTED / RECTIFICATION_REQUIRED / DISPUTED。

平台应按合同约定提醒逾期未验收。是否构成视为验收、是否触发付款义务，必须依据有效合同条款和适用法律判断。平台不得仅凭系统超时自动认定工程质量合格。

## 11. 付款、退款和结算

### 11.1 付款计划

付款节点来自合同，例如预付款、达到约定施工进度后的阶段款、验收后的尾款或其他合法约定款项。每个节点记录触发条件、应付金额、付款期限和凭证，不默认用统一比例覆盖所有住宅工程。

### 11.2 状态分离

至少分开记录：
- 业务付款义务：未到期、待支付、部分支付、已满足合同条件、争议中。
- 支付请求：待创建、已提交、处理中、失败、关闭。
- 外部支付结果：成功、失败、撤销、退款中、部分退款、已退款。
- 外部结算结果：未结算、处理中、已结算、延迟、失败。
- 平台服务费：应收、已收、冲销或争议。

支付成功以合作机构可核验结果为准；结算到账以机构结算记录及适当账户核对为准。

### 11.3 退款

退款可能来自合同依法或依约解除、双方协商、未履行部分应退、重复支付或差错、争议处理结果及其他法定/约定情形。

处理步骤：发起退款并说明原因；校验原合同、原支付交易和申请权限；核算可退金额及已履行部分；依据合同和支付机构规则取得必要确认；通过原支付机构支持的流程提交；以外部退款结果更新记录；退款失败或超时进入人工核查。

平台不能凭内部余额或订单状态自行完成第三方交易资金退款。

### 11.4 取消与解除

区分尚未签约的需求关闭、已报价未签约的报价撤回/失效、已签约未开工的合同解除、已开工后的部分履行/结算/解除，以及因安全、违法或资质问题暂停/终止。

已签合同不能通过删除订单实现取消。应保留解除依据、已完成工作、材料采购、合理费用、双方确认和退款/结算记录。费用承担按合同和法律判断。

## 12. 投诉、争议与售后

### 12.1 投诉分类

服务商失联或拒绝履约；报价与最终收费不一致；材料规格不一致；施工延期；质量争议；现场损坏或财产损失；退款争议；主体或资质信息异常；人身安全或其他重大风险。

### 12.2 分级处理

| 级别 | 情形 | 处理 |
|---|---|---|
| P0 紧急 | 人身安全、重大事故、持续危险 | 提示避险、暂停相关服务流程、联系适当应急渠道并升级 |
| P1 重大 | 疑似违法施工、重大质量/财产风险、主体或资金异常 | 暂停相关交易功能，专人核查，保全证据 |
| P2 一般争议 | 价格、工期、材料、整改和退款争议 | 双方陈述、证据收集、协商和必要专业意见 |
| P3 服务体验 | 沟通、响应、预约等一般问题 | 客服工单和服务改进 |

平台应明确紧急投诉响应方式，不得宣传为替代110、119、120或当地专业应急服务。

### 12.3 争议处理边界

平台可以收集订单、合同、报价、沟通和施工记录；通知双方提交证据；组织协商并记录结果；按公开规则处理账号、展示和交易权限；建议双方寻求检测、鉴定、调解、仲裁或诉讼。

平台不得在没有专业依据时宣称一方必然承担工程质量责任；不得把客服结论表述为司法裁判或法定质量鉴定；不得擅自扣留、划转或处分第三方交易资金；不得删除对任何一方不利的交易证据。

### 12.4 售后与质保

售后承诺应来自真实服务合同和实际责任主体。平台可以提供工单入口、提醒和进度跟踪，但未承担自营责任或未取得服务商授权时，不得承诺由平台无限期承担所有施工质量责任。

## 13. 派单、服务费与评价

### 13.1 派单规则

推荐/派单可综合服务类目和区域、准入状态及必要资质范围、可用时间、历史有效履约数据、业主偏好和风险限制。不得只按付费金额决定安全敏感工程的推荐结果；付费推广应明确标识。

### 13.2 服务费规则

明确收费对象、收费触发点、计费基数和费率/固定金额、税务及开票主体、取消退款变更时的调整、会员或增值服务费、规则版本和生效时间。

平台不得在成交后追溯修改已确认收费规则。收费路径遵循《04 支付与结算合规》，不得以内部账本扣减替代合法资金处理。

### 13.3 评价规则

评价应与真实交易或服务体验相关；提交者必须具有相应交易参与关系；不得购买、伪造或诱导虚假评价；修改、隐藏和申诉有明确规则及操作记录；平台可治理违法、侵权、泄露隐私或明显虚假内容，但不应仅因评价负面就删除。

## 14. 超时与异常处理

| 场景 | 默认处理建议 | 说明 |
|---|---|---|
| 需求待补充超时 | 提醒后关闭或归档 | 可重新提交 |
| 报价过期 | 自动标记 EXPIRED | 不可直接接受 |
| 服务商未响应 | 提醒并允许邀请其他服务商 | 不自动认定违约 |
| 预约无法确认 | 提醒双方并允许重新排期 | 记录沟通事实 |
| 施工记录迟交 | 标记补录 | 保留补录时间 |
| 变更未确认 | 维持原合同版本 | 不得按未确认变更收费 |
| 业主未验收 | 按合同提醒和升级 | 不自动视为质量合格 |
| 支付回调丢失 | 主动查询机构结果 | 超时不等于支付失败 |
| 退款失败 | 建立人工差错工单 | 不直接改成退款成功 |
| 投诉超时 | 升级客服负责人 | 保留处理轨迹 |
| 证照过期 | 暂停相关范围新接单 | 存量合同单独评估 |

具体时限应按服务类型、城市运营能力、合同约定和支付机构SLA配置；不应在缺乏验证时写死为全平台统一规则。

## 15. 操作审计与证据

以下动作必须记录操作者、角色、时间、对象、动作前后状态及必要原因：用户和组织认证；服务商准入、暂停、恢复和退出；需求审核和关闭；报价提交、撤回、接受和拒绝；合同确认、变更和解除；施工记录新增、补录和更正；验收、整改和争议；支付/退款请求和外部回调；投诉结论、账号限制和申诉；平台服务费规则变更。

附件应记录上传者、上传时间、关联业务对象和文件完整性信息。敏感个人信息按最小必要原则展示和访问；证据材料不得被无权限人员任意下载或传播。

## 16. 商业工程规则框架（后续阶段）

商业工程不套用住宅单订单流程。后续单独设计：
1. 发包主体和项目资料核验。
2. 是否依法必须招标及适用程序识别。
3. 项目拆分为专业包/标段的规则。
4. 承包主体资质、许可、承包范围和人员要求核验。
5. 报名、资格审查、报价和评审留痕。
6. 项目合同、专业分包合同和实际履约关系。
7. 工程量清单、进度申报、签证和变更。
8. 阶段验收、竣工验收、结算和质保。
9. 各合同主体对应的付款、发票和结算路径。
10. 工程安全、质量、资料归档和争议处理。

是否必须招标、承包资质要求、分包合法性和工程质量责任，须根据具体项目属性与现行法律法规判断，不能由平台算法自动替代。

## 17. MVP 端到端验收场景

### 场景A：正常成交
业主提交需求；平台审核通过；合格服务商报价；业主接受某一报价版本；双方确认同一合同版本；订单创建并预约；服务商提交施工记录；双方确认变更（如有）；服务商提交验收申请；业主验收或发起整改；按合同和支付机构流程完成付款/退款状态核对；订单归档并可查看证据链。

### 场景B：报价变更
服务商提交报价版本1和版本2；业主只能接受当前有效版本；合同记录被接受的报价版本；历史版本仍可追溯。

### 场景C：合同后变更
合同生效后服务商发起工程量/材料变更；业主未确认时，系统不得将新增费用计入已确认应付金额；双方确认后生成变更记录并更新业务付款计划。

### 场景D：支付异常
支付请求已提交但回调未到；系统主动查询机构状态；不因超时直接标记成功或失败；重复回调不重复记账或触发业务动作；机构退款结果与平台记录可对账。

### 场景E：投诉与暂停
业主发起质量或安全投诉；平台记录证据并按风险等级分派；必要时暂停服务商相关类目新接单；不擅自判定工程质量责任或划转资金；处理过程、双方陈述和结果可追溯。

### 场景F：权限异常
无权组织成员不能签署企业合同；被撤销授权的成员不能执行后续高风险动作；历史操作仍保留原操作者和当时授权快照。
