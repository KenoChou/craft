# 产品架构设计

> 文档状态：讨论稿 / v0.1  
> 更新时间：2026-11-20  
> 适用范围：中国大陆水电安装服务与工程交易平台  
> 上游文档：01 商业定位、02 商业模式与法律主体关系、03 交易模型、04 支付与结算合规  
> 本文目标：定义产品边界、角色入口、核心模块、交易主链路和分阶段建设范围；本阶段不展开数据库表或技术实现。

## 1. 产品定义

本平台是面向水电安装产业的交易与履约平台。首期以住宅水电安装、维修和局部改造为切入点，连接业主与真实服务提供者，完成从需求发布到服务履约、验收和售后的闭环；随后扩展商业工程项目交易，再逐步提供施工企业数字化工具和材料供应链服务。

产品不是：
- 只发布联系方式的分类信息网站；
- 以简历和招聘为中心的劳务平台；
- 平台统一雇佣所有施工人员的施工公司；
- 首期就覆盖所有工程专业的通用工程ERP；
- 由平台自行归集、保管和划转第三方交易资金的资金平台。

## 2. 产品架构原则

1. **交易闭环优先。** 首期先让一笔住宅安装订单能够真实完成，而不是先做庞大的内容社区、商城或企业管理套件。
2. **用户账户与经营主体分离。** 一个自然人账号可以代表个人身份，也可以作为企业成员操作；合同签约方、经营者、履约方和收款方必须独立明确。
3. **住宅订单与商业项目分开。** 住宅以单次服务订单为中心；商业工程以项目、专业包、合同、施工任务和付款节点为中心。
4. **平台撮合与平台自营显著区分。** 自营服务必须清晰标识，不得让消费者误以为平台内第三方服务均由平台直接提供。
5. **业务记录与资金事实分离。** 平台记录支付请求和外部支付结果，不自建用户可提现钱包，不将内部账本描述为资金托管。
6. **资质与准入按服务范围配置。** 不以一次实名认证替代经营主体、许可、资质和具体施工范围核验。
7. **城市密度优先于全国铺量。** 先在一个城市形成足够的业主需求和可靠服务商供给，再复制城市运营模型。
8. **渐进式建设。** MVP保留未来扩展接口，但不提前实现未验证的复杂能力。

## 3. 用户与业务角色

### 3.1 用户账户和主体

- User：登录账户、联系方式、认证状态和个人设置。
- PersonProfile：自然人个人资料。
- Organization：企业、个体工商户或其他组织主体。
- OrganizationMember：组织成员及其角色、权限和有效期。
- ProviderProfile：施工人员或服务提供者的服务资料、技能、服务区域和审核状态。
- BusinessQualification：经营主体证照、许可/资质材料、核验结果和有效期。

同一个用户可以创建或加入多个组织；同一个组织可有负责人、管理员、项目经理、施工人员和财务等成员。不能把登录用户ID直接当成合同主体。

### 3.2 面向用户的主要角色

| 角色 | 核心目标 | 主要操作 |
|---|---|---|
| 业主/需求方 | 找到可信服务商并完成安装维修 | 发布需求、比较报价、签约、跟踪、验收、售后 |
| 个人服务提供者 | 展示能力并获得合适订单 | 完善资料、提交报价、排期、施工记录、响应售后 |
| 施工企业 | 获取业务并管理团队履约 | 企业认证、成员管理、报价、合同、项目进度 |
| 工程发包/项目需求方 | 寻找合格承包主体 | 发布项目、邀请/筛选、评审报价、合同与验收 |
| 工程承包商/专业施工企业 | 获取专业工程并组织履约 | 资质资料、项目报名、专业包报价、施工任务管理 |
| 材料供应商 | 获得材料采购需求 | 商品目录、询价响应、报价和订单协作 |
| 平台运营人员 | 保障交易安全和平台秩序 | 主体审核、内容巡检、投诉处理、交易风控、运营分析 |

一个人可能同时是业主、施工人员或企业负责人。界面可以切换工作身份，但权限必须由账户、组织成员关系和具体交易参与关系共同决定。

## 4. 产品端划分

### 4.1 业主端（App / H5 / 小程序）

MVP重点页面：
- 首页：住宅安装、维修、局部改造入口；城市与服务区域。
- 发布需求：服务类型、地址区域、房屋/现场情况、面积或工程量、期望时间、预算区间、图片/视频和补充说明。
- 需求详情：需求状态、服务商报价、平台推荐或派单结果。
- 服务商详情：经营主体信息、服务范围、可核验资质、案例、评价、服务说明。
- 报价比较：报价总额、项目范围、材料/人工口径、工期、质保和排除项。
- 合同确认：签约主体、服务范围、价格、工期、付款节点、变更和售后条款。
- 订单进度：预约、进场、施工记录、变更确认、验收申请。
- 验收与售后：验收项、问题整改、评价、投诉和售后申请。
- 消息中心：报价、合同、施工节点、支付结果和售后通知。

### 4.2 服务商端（App / 小程序）

MVP重点页面：
- 入驻与身份核验。
- 个人/组织资料及经营信息。
- 服务项目、技能、服务区域和可接单状态。
- 需求大厅或定向邀请。
- 需求详情和报价提交。
- 订单确认、预约和排期。
- 施工记录、现场照片、材料使用记录。
- 变更申请及业主确认。
- 验收申请、整改和售后响应。
- 交易记录、平台服务费记录和机构结算状态查询（仅展示经核验的外部结果）。

不在首期提供平台内部余额、自由提现或商户之间转账功能。

### 4.3 企业端（Web 管理台）

MVP仅提供履约所需的轻量能力：
- 企业主体资料、证照和服务范围。
- 成员邀请、角色权限。
- 企业服务项目和服务区域。
- 报价与订单列表。
- 订单责任人、施工人员分配。
- 施工记录和验收材料。
- 合同与文件归档。
- 售后和投诉协作。

增长期再增加多项目看板、成本预算、人员排班、材料采购、项目毛利、客户管理和经营报表。

### 4.4 平台运营后台（Web）

MVP必须具备：
- 用户与主体审核。
- 服务商入驻、证照和资质材料审核。
- 服务类目、区域和服务规则管理。
- 需求与报价巡检。
- 订单和合同查询。
- 交易异常与支付对账状态查询。
- 投诉、纠纷、退款协作和售后工单。
- 评价治理、违规处理和申诉。
- 平台服务费规则及记录。
- 操作审计、权限管理和基础经营数据。

运营后台不能提供绕过支付机构的资金划转按钮；不能通过人工修改订单状态伪造支付成功或结算到账。

### 4.5 材料供应商端

首期只做轻量材料目录与询价协作：
- 供应商主体资料。
- 材料分类、品牌、规格、单位和参考信息。
- 询价需求接收与报价。
- 供应商联系方式及交易主体展示。

首期不强制把材料采购款纳入平台统一收款。材料交易应明确买卖双方、销售主体、交付责任、发票和收款主体。

## 5. 业务域与模块边界

| 业务域 | 核心模块 | MVP | 后续 |
|---|---|---|---|
| 身份与组织 | 账户、个人资料、组织、成员、角色权限 | 必须 | 多组织精细权限 |
| 服务供给 | 服务商档案、技能、区域、服务目录 | 必须 | 能力等级、培训、保险等 |
| 需求与撮合 | 需求发布、报价、邀请、匹配 | 必须 | 智能推荐、区域供需调度 |
| 住宅交易 | 服务订单、合同、预约、变更 | 必须 | 标准化套餐、复杂工程量清单 |
| 履约管理 | 施工记录、材料记录、验收、整改 | 必须 | 工序模板、质量巡检 |
| 交易支付 | 支付请求、外部支付状态、退款、对账 | 依赖合规机构 | 经验证的机构分账产品 |
| 售后治理 | 评价、投诉、争议、售后工单 | 必须 | 质量追踪与风险模型 |
| 企业项目 | 项目、专业包、报名、合同、节点 | 暂缓完整建设 | 增长期/扩张期 |
| 材料供应链 | 目录、供应商、询价 | 轻量 | 采购订单、物流、质量追溯 |
| 平台运营 | 审核、巡检、风控、运营数据 | 必须 | 多城市运营和策略中心 |
| 企业SaaS | 项目、人员、成本、报表 | 轻量订单协作 | 增长期重点 |
| 数据与分析 | 漏斗、供需、履约、投诉、收入 | 基础指标 | 城市经营分析 |

## 6. 住宅服务交易主链路

~~~text
业主发布需求
    ↓
平台校验需求信息与服务范围
    ↓
自主撮合 / 平台派单 / 定向邀请
    ↓
服务商查看需求并提交报价
    ↓
业主比较报价与服务商资料
    ↓
选定服务商，明确真实签约主体
    ↓
双方确认服务合同及付款节点
    ↓
按合规支付产品发起付款
    ↓
预约进场 → 施工记录 → 变更确认
    ↓
服务商申请验收 → 业主验收/提出整改
    ↓
按合同及支付机构规则完成付款/退款
    ↓
评价 → 售后 → 订单归档
~~~

关键规则：
- 报价必须有版本，修改报价不能覆盖已被业主接受的历史版本。
- 合同必须锁定报价版本、服务范围、排除项和付款条件。
- 施工范围变化必须形成变更单并由相关方确认。
- 施工记录应关联订单、施工人员、时间和附件。
- 验收与付款是不同业务事实；验收通过不等于支付机构已结算。
- 争议订单进入人工处理流程，不允许通过简单改状态跳过争议。

## 7. 商业工程产品入口

商业工程不在MVP阶段完整上线，但产品结构预留独立入口和对象模型。

~~~text
项目需求发布
    ↓
项目资料与发包主体核验
    ↓
项目拆分为专业包/标段
    ↓
邀请或公开征集承包主体
    ↓
资格材料核验与报价评审
    ↓
专业包合同签署
    ↓
施工任务与里程碑
    ↓
进度申报 → 工程量确认 → 变更签证
    ↓
阶段验收 → 竣工验收 → 结算
    ↓
质保义务与售后
~~~

增长期应重点支持项目、专业包、承包商报名、工程量清单、合同、施工任务、进度节点、变更签证和竣工资料。工程资金按各真实合同主体和经确认的银行/支付机构方案处理，平台不建立项目资金池。

## 8. 三种交易模式的产品表现

| 模式 | 产品入口 | 平台职责 | 合同关系 |
|---|---|---|---|
| 自主撮合 | 需求大厅/报价市场 | 提供信息、规则、沟通和交易工具 | 业主与服务商直接签约 |
| 平台派单 | 推荐/派单任务 | 根据规则分发需求、记录接受情况 | 原则上仍由业主与实际服务商签约，具体以合同为准 |
| 平台自营 | 平台自营服务专区 | 平台作为真实经营主体履约 | 业主与平台经营主体签约 |

自营与第三方服务必须在列表、详情、合同、售后和消费者沟通中清晰区分。平台不能仅因控制派单或服务流程，就默认成为施工合同主体；也不能通过标注“平台担保”模糊真实责任。

## 9. MVP 范围与暂缓清单

### 9.1 MVP 必须交付

1. 一个试点城市和明确服务区域。
2. 住宅安装、维修、局部改造的服务类目。
3. 业主需求发布和需求管理。
4. 服务商入驻、身份/主体核验和资料展示。
5. 报价、比较、选择和撮合。
6. 合同确认与版本留存。
7. 预约、施工记录、变更和验收。
8. 售后、评价、投诉和纠纷处理。
9. 银行/持牌支付机构方案确认后的支付请求、外部状态、退款和对账接入。
10. 平台运营后台和基础数据分析。

### 9.2 MVP 暂缓

- 完整商业工程招投标与工程项目管理。
- 复杂材料商城、仓储、物流和供应链金融。
- 平台自有钱包、充值、提现、商户间转账。
- 平台自行控制的担保交易、资金冻结和分账。
- 全套施工企业ERP、财务核算和成本管理。
- 暖通、消防、弱电、机电等多专业全量类目。
- 全国跨城市派单和复杂智能调度。
- 基于算法自动判定施工质量或争议责任。

## 10. 核心产品指标

首期不以注册量或DAU作为唯一目标，重点衡量真实交易质量：

| 指标 | 定义 |
|---|---|
| 有效需求数 | 信息完整且通过平台基本校验的需求 |
| 报价响应率 | 至少收到一份有效报价的需求占比 |
| 成交转化率 | 形成有效服务合同的需求占比 |
| 首次响应时长 | 需求发布至首个有效服务商响应的时间 |
| 履约完成率 | 按规则完成验收的有效订单占比 |
| 按期完成率 | 在约定工期内完成的订单占比 |
| 变更率 | 发生合同范围/金额变更的订单占比 |
| 退款/争议率 | 出现退款或争议的订单占比 |
| 售后发生率 | 完成订单中产生售后工单的比例 |
| 服务商复接率 | 服务商在观察期内再次完成有效订单的比例 |
| 城市供需覆盖 | 各服务区域内有效需求与可履约供给的匹配程度 |
| 平台单位经济 | 单笔平台收入减去获客、支付、客服、风控等可变成本 |

## 11. 合规能力必须成为产品功能

根据《电子商务法》和《网络交易监督管理办法》，平台不能把主体审核、公示、交易记录、平台规则、消费者权益和经营者治理留给线下人工随意处理。

产品应支持：
- 平台内经营者身份、地址、联系方式及适用许可/资质信息核验和登记。
- 经营主体信息公示及变更更新。
- 已登记经营者与依法未登记经营者的清晰区分。
- 服务信息和交易信息的完整留存、访问控制与审计。
- 平台服务协议和交易规则的版本管理。
- 违规内容巡检、处理、通知和申诉。
- 投诉举报、消费纠纷调解和依法协助监管。
- 按现行规定完成平台内经营者信息报送及相关协作。

《网络交易监督管理办法》对平台内经营者身份信息核验更新、信息公示、经营者身份区分、交易信息保存和报送等有具体要求；其中平台内经营者身份信息保存期限、交易信息保存期限等，应按现行适用条款配置，不能简单只保留订单主表。相关实现须由法务确认业务适用性和数据保存策略。

参考：
- [《中华人民共和国电子商务法》—市场监管总局](https://www.samr.gov.cn/zfjcj/tzgg/art/2023/art_d337c3291e8b40459ca03dea54395856.html)
- [《网络交易监督管理办法》—市场监管总局](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2025/art_4b47c79b8d994a42bba4835997688faa.html)
- [《网络交易平台经营者合规指引》相关政策页面—北京市政府](https://www.beijing.gov.cn/zhengce/zhengcefagui/202505/t20250521_4094788.html)

> 注：上述为产品需求识别，不替代法律意见。保存期限、报送口径、自然人经营者登记例外及不同服务类别资质要求，均应在正式上线前按届时有效规则逐项核验。

## 12. 分阶段路线图

### 阶段一：单城市住宅交易MVP
- 住宅安装、维修和局部改造。
- 业主端、服务商端、运营后台。
- 需求、报价、合同、施工、验收、售后闭环。
- 合规支付机构接入和对账。
- 建立本地服务商供给和质量治理机制。

### 阶段二：城市网络与企业协作
- 多区域服务覆盖。
- 施工企业组织和成员管理。
- 派单、排期、订单协作和服务商等级。
- 多项目基础管理。
- 企业会员和经营数据分析。

### 阶段三：商业工程交易
- 项目发布、专业包、承包商报名。
- 资质材料核验和报价评审。
- 工程合同、里程碑、变更签证、验收和结算资料。
