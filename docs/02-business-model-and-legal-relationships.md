# 商业模式与法律主体关系

> 文档状态：讨论稿 / v0.1  
> 更新时间：2026-11-20  
> 上游文档：01-business-positioning.md  
> 本文用于明确商业关系和待核验事项，不构成法律意见。具体经营模式应由中国大陆执业律师、税务专业人士及支付合作机构结合实际业务确认。

## 1. 本文目标

本文件回答五个问题：

1. 平台在交易中提供什么服务、收取什么费用？
2. 业主、施工人员、个体工商户、施工企业和工程承包商之间如何建立关系？
3. 谁是服务合同的签约主体，谁承担施工履约责任？
4. 平台如何避免名义撮合、实际自营或不清晰的代理关系？
5. 合同流、业务流、资金流和发票流如何保持一致？

核心原则：**业务事实、合同关系、资金路径、票据处理必须相互匹配。** 不能先设计一个方便的产品流程，再用合同文字包装成另一种经营模式。

## 2. 平台的业务收入与合同关系

### 2.1 平台提供的服务

初期建议将平台服务限定为可明确描述和留痕的数字化交易服务：

- 需求信息发布与展示。
- 服务商信息展示、身份核验和资质材料管理。
- 搜索、匹配、报价和沟通工具。
- 订单及项目协作工具。
- 合同签署工具或第三方电子签约服务接入。
- 施工过程记录、验收记录和售后沟通工具。
- 评价、投诉受理和争议协助。
- 面向企业的项目、人员、材料和经营管理软件。

平台提供上述服务，并不当然成为施工合同的当事人；但平台仍需承担适用法律规定的网络交易平台经营者责任。

### 2.2 平台可能签订的合同

| 合同/协议 | 签约双方 | 主要内容 |
|---|---|---|
| 平台用户协议 | 平台—用户 | 账户、使用规则、平台服务边界 |
| 平台商户/服务商协议 | 平台—经营者 | 入驻、信息核验、经营规则、服务费、违规处理 |
| 平台服务订单合同 | 业主—实际服务提供方 | 施工范围、价格、工期、验收、质保、变更 |
| 工程项目合同 | 建设单位/发包方—依法适格承包主体 | 工程范围、价款、进度、质量、安全、结算 |
| 企业 SaaS 服务协议 | 平台—企业客户 | 软件功能、订阅期限、服务等级、数据处理 |
| 材料买卖合同 | 买方—实际销售主体 | 品名、规格、数量、价格、交付、质量和售后 |

实际交易中可能存在多个合同。每份合同都应说明服务对象、履约义务、费用、违约责任和争议解决方式。

### 2.3 收入分类

平台收入至少分为以下几类，不能混为一笔“平台抽成”：

| 收入类型 | 经济实质 | 需要核验的事项 |
|---|---|---|
| 撮合服务费 | 平台为撮合服务收取费用 | 收费对象、触发条件、退款和开票 |
| 派单服务费 | 平台提供特定派单/运营服务 | 派单实际内容、定价权和履约控制程度 |
| 工程项目服务费 | 平台提供项目交易或协同服务 | 是否仅提供信息/工具，还是参与项目经营 |
| SaaS 订阅费 | 软件使用和技术服务 | 服务范围、计费周期、服务交付 |
| 材料佣金/服务费 | 供应商推广或交易服务 | 平台是否为销售方、是否控制商品或交付 |
| 自营工程收入 | 平台经营主体直接承接工程 | 经营资质、施工组织、质量安全、成本和税务 |

平台收入确认和纳税义务应根据合同约定、实际履约、控制权及适用税法判断，不能简单按平台页面显示的订单总额确认收入。

## 3. 参与主体及法律身份

### 3.1 自然人用户

自然人可能是业主、施工人员、项目联系人、企业负责人或组织成员。自然人账户本身不等于经营主体。

需要分别记录：
- 自然人身份核验信息。
- 个人技能和从业经历。
- 经营者身份（如适用）。
- 所属组织及成员权限。
- 特定交易中的参与角色。

### 3.2 个体工商户

个体工商户是经营主体，不应简单等同于“个人施工人员”。平台应根据业务和法律要求核验其登记信息、经营状态、经营范围及相关许可资质。

在具体交易中，应明确是个体工商户作为服务提供方签约，还是经营者以其他合法身份提供服务。签约、收款和开票安排应与真实经营主体相符。

### 3.3 施工企业

施工企业可能以服务商、专业施工单位或工程合同承包主体身份参与交易。平台应核验其登记状态、适用资质许可、承包范围、人员及项目能力。

企业账户下的项目经理、施工人员和财务人员属于组织成员权限，不应被误认为各自独立承担企业合同责任。

### 3.4 工程承包商与总承包单位

“工程承包商”是业务称谓，不是对法定资质的替代。需要结合具体工程类型、承包范围、合同结构及现行建筑市场管理规定判断其能否承接。

涉及总承包、专业分包、劳务作业等关系时，必须核验相关主体资格、合同范围和禁止性规定。平台不能通过撮合功能规避违法发包、转包或违法分包风险。

### 3.5 材料供应商

材料供应商可以是生产商、经销商、零售商或配送服务商。需要区分：
- 平台仅展示供应商信息。
- 平台提供询价和线索服务。
- 平台作为交易撮合方。
- 平台自身采购并转售材料。

最后一种属于不同的经营模式，涉及货权、质量责任、售后、发票、库存和税务，不应与信息撮合混用。

## 4. 三种平台经营模式

### 4.1 模式 A：第三方撮合平台（MVP 推荐）

**基本结构**

业主与实际施工服务提供方建立施工服务合同；平台与双方分别建立平台服务关系。平台不成为施工合同的当然当事人。

**平台职责**
- 提供信息和交易工具。
- 对平台内经营者依法进行身份核验和管理。
- 建立规则、公示收费、处理投诉。
- 留存交易过程记录，按法律要求配合监管。
- 按平台服务协议收取自身服务费用。

**优势**
- 初期不必自行组织所有施工队伍。
- 可利用区域内既有施工供给。
- 经营扩张更依赖供需组织和平台能力。

**风险与限制**
- 平台仍承担法定平台经营者义务。
- 服务商质量参差，需要准入、评价和争议治理。
- 不能以撮合为名实质控制全部施工经营活动。
- 平台服务费与施工价款必须清晰区分。

### 4.2 模式 B：代理/受托服务

平台或指定主体受一方委托，按授权处理特定事务。

必须明确：
- 委托人是谁。
- 授权范围和期限。
- 是否有权代为报价、签约或确认变更。
- 行为后果由谁承担。
- 费用由谁支付。
- 是否涉及代收款；若涉及，资金路径是否合法、合作机构是否支持。

代理权限不能从“平台帮用户操作”中自动推定。尤其不得把代理协议当作规避支付监管的工具。

**建议：** MVP 不采用宽泛、模糊的通用代理模式。确需代理时，针对具体场景设计独立授权书和合同。

### 4.3 模式 C：平台自营施工

平台或独立关联经营主体直接向客户承诺施工服务，并承担相应合同义务。

需要具备与业务相匹配的：
- 经营主体及经营范围。
- 适用资质、许可和人员条件。
- 施工组织、质量控制和安全管理能力。
- 采购、用工、分包和售后能力。
- 工程保险及风险管理安排（视业务需要）。
- 合同、收入、成本、发票和纳税管理。

**优势：** 服务标准、报价和履约过程更容易统一管理。

**风险：** 质量、安全、工期、人员、材料、售后及项目亏损风险会更多集中到自营主体；扩张需要投入真实运营能力。

平台若同时经营撮合业务和自营业务，应明确区分经营主体、页面标识、合同、收款账户、发票和责任承担，避免消费者混淆。

## 5. 典型交易关系图

### 5.1 住宅第三方撮合

业主 ——（施工服务合同）—— 实际施工服务提供方

平台 ——（平台用户协议）—— 业主  
平台 ——（平台服务/商户协议）—— 服务提供方

施工服务价款：按合规支付安排由业主支付至适格收款主体。  
平台服务费：按平台服务协议向约定付款方收取。

说明：图示仅表达合同关系的基本分层。具体支付产品、交易资金路径和结算方式必须由银行/持牌支付机构确认，不应据此推导平台可以自行归集或划转商户资金。

### 5.2 商业工程项目撮合

建设单位/发包方 ——（工程合同）—— 依法适格的承包主体

承包主体 ——（依法成立的分包、采购或用工关系，如适用）—— 专业施工单位/材料供应商/施工人员

平台向项目参与方提供信息、撮合或项目协同软件服务，并根据独立的平台服务协议收取相应费用。

说明：平台不能替代建设单位、总承包单位或专业承包单位承担其法定职责；不得通过平台流程促成违法转包、违法分包或无资质承揽。

### 5.3 平台自营

业主/客户 ——（自营工程/服务合同）—— 平台自营经营主体

平台自营经营主体再依据真实业务，建立合法采购关系、用工关系或施工合作关系。

此模式下，平台自营经营主体承担合同约定及法律规定的相应经营和履约责任。平台主体与关联公司之间的关系也应真实、清晰、可审计。

## 6. 合同流、业务流、资金流、发票流

四条流必须逐笔核对。

| 流程 | 需要回答的问题 | 系统应留存的证据 |
|---|---|---|
| 合同流 | 谁向谁承诺提供什么服务？ | 合同版本、签署主体、签署时间、变更记录 |
| 业务流 | 谁实际施工、交付、验收？ | 进场记录、施工记录、材料记录、验收单 |
| 资金流 | 谁付款、谁收款、通过何种支付产品？ | 支付机构交易号、退款记录、结算流水、对账结果 |
| 发票流 | 谁向谁开具何种发票？ | 开票主体、购买方、项目内容、金额和发票信息 |

异常情形示例：
- 合同由施工企业签署，资金却长期进入无关个人账户。
- 平台合同称仅撮合，但平台统一承揽、统一报价、统一组织施工并承担全部交付。
- 平台收取全额工程款后，再自行向多个施工人员转款。
- 平台收取的所谓保证金或余额可由平台任意挪用。
- 发票主体与实际销售/服务提供主体不一致。

发现异常时应阻断或人工复核，而不是仅通过修改订单状态继续交易。

## 7. 支付与二清风险控制

### 7.1 需要区分的三类资金

1. **施工/工程合同价款**：属于真实施工合同项下的交易资金，收款主体和结算路径应与合同及支付机构产品规则相符。
2. **平台服务费**：属于平台根据独立平台服务合同收取的自身服务收入。
3. **平台自营合同价款**：属于实际自营经营主体履行自身合同所收取的价款。

这三类资金不可在系统中无差别归入一个“平台余额”。

### 7.2 MVP 资金边界

- 不自建资金池。
- 不提供平台可自由划转的商户钱包。
- 不把内部账本余额描述成真实可提现资金。
- 不自行决定第三方商户资金的划拨和结算。
- 不承诺支付机构未书面确认支持的担保交易、冻结、分账或延迟结算功能。
- 不以“用户授权”替代支付业务许可或支付机构规则。
- 退款、部分退款、合同变更和争议款项应遵循合同及合作支付产品规则。

### 7.3 上线前必须取得的确认

向拟合作银行或持牌支付机构书面确认：
- 平台及各类商户的进件主体和准入要求。
- 住宅服务和商业工程交易是否属于支持场景。
- 交易资金收款主体和结算账户要求。
- 是否支持分账、延迟结算、退款、部分退款和手续费处理。
- 交易纠纷、拒付、异常交易和商户退出时的资金处理规则。
- 对平台、商户和关联经营主体的协议要求。

仅完成支付接口接入，不代表资金安排已经合规。

## 8. 经营者准入与持续治理

建议按风险分级，而不是所有供给方只上传一张身份证即可接单。

| 供给主体 | 基础核验 | 业务专项核验 |
|---|---|---|
| 自然人服务提供者 | 身份、联系方式、技能资料 | 业务范围、从业能力、适用的经营要求 |
| 个体工商户 | 登记信息、经营状态 | 经营范围、许可资质、收款和开票信息 |
| 施工企业 | 主体登记、法定代表人/授权人 | 资质证书、许可范围、人员、项目能力 |
| 工程承包主体 | 主体登记、授权关系 | 工程类别、资质等级、承包范围、项目条件 |
| 材料供应商 | 主体登记、联系人 | 产品合规、质量文件、售后及配送能力 |

平台应提供：
- 资质有效期提醒和到期限制。
- 主体变更和账号权限变更记录。
- 投诉、违规、履约和质量事件记录。
- 重大风险订单人工审核。
- 经营者退出、冻结和申诉机制。
- 资质材料访问控制和个人信息保护。

具体核验项目须根据经营品类、地区和现行法规确定，避免将不适用的许可要求机械套用到所有住宅维修服务。

## 9. 待律师、税务及支付机构确认的事项

以下事项列为上线前的阻断性核验，不在文档中预设结论：

1. 目标住宅安装、维修、局部改造范围分别涉及哪些经营许可或施工资质要求。
2. 平台撮合、派单和服务商管理的具体设计是否使平台承担超出一般撮合的经营或履约责任。
3. 不同施工供给方以自然人、个体工商户或企业身份交易时，合同、收款和开票应如何安排。
4. 商业工程中不同工程类别的承包、专业分包和劳务作业边界。
5. 拟采用的银行/持牌支付机构产品是否支持本平台的交易场景及资金路径。
6. 平台服务费、工程服务费、SaaS 订阅费和材料服务费的税务处理。
7. 施工人员与平台、施工企业之间可能形成的劳动、劳务或其他法律关系。
8. 电子合同、现场照片、施工记录、验收确认和聊天记录的证据留存及数据保护要求。
9. 平台争议处理、退款协助、消费者保护和质量投诉机制的责任边界。

## 10. 本阶段建议决策

以下是产品设计建议，不代表用户已经确认：

| 决策 | 建议 | 状态 |
|---|---|---|
| 初期主模式 | 第三方交易撮合平台 | 待用户确认 |
| 平台代理 | 不作为通用默认模式，具体场景单独授权 | 待用户确认 |
| 平台自营 | MVP 暂不作为主模式，未来独立评估 | 待用户确认 |
| 合同签署 | 业主与实际服务提供方签施工合同；平台另签平台服务协议 | 待法律核验 |
| 工程交易 | 由依法适格的工程主体签署工程合同 | 待法律核验 |
| 支付 | 通过银行/持牌支付机构确认的产品实现 | 待机构确认 |
| 材料交易 | 初期先做目录、询价和供应商撮合 | 待用户确认 |

## 11. 下一步

在本文件的经营模式得到确认后，进入 03-transaction-models.md，具体设计：

- 住宅服务订单的参与者、报价、合同、施工、验收、售后和状态机。
- 商业工程项目的发布、报名、资格审查、报价、合同、变更、阶段验收和结算。
- 两类交易共享哪些基础能力，哪些字段和流程必须隔离。
- 自主撮合、平台派单、企业工程交易的差异化规则。

**维护原则：** 所有主体关系必须从真实业务出发；任何合同模板、支付流程和产品交互都不能与实际履约关系相矛盾。
