# MVP 实施路线图与验收标准

> 状态：建议稿，待项目决策人确认。本文将规划文档转化为可执行的验证与交付阶段，不代表已批准预算、团队规模或上线日期。

## 1. 实施目标与范围

首期目标不是一次性建设全国性综合工程平台，而是在一个城市、有限服务品类内，验证住宅水电安装服务交易闭环：

1. 需求方能够清晰发布真实需求。
2. 平台能够审核需求并匹配合适服务商。
3. 服务商能够提交结构化报价，需求方能够比较并选择。
4. 双方能够确认合同、服务范围、价格和工期。
5. 施工过程、现场情况及变更有记录。
6. 验收、付款、退款和售后能够按真实合同及合规支付路径处理。
7. 平台能够追踪服务质量、投诉、订单转化和单位经济。

首期建议聚焦住宅水电安装、维修和局部改造中的一至两个细分品类。具体城市和品类必须经调研确定。

## 2. 实施前置决策（Gate 0）

以下事项未明确前，不进入完整交易支付开发：

- 平台运营主体及其经营范围。
- 首期采用第三方撮合还是平台自营；建议默认第三方撮合。
- 需求方、实际服务商、合同签约方、开票方、收款权利主体的对应关系。
- 首期服务品类的资质、许可、人员能力和安全要求。
- 支付机构的产品能力、商户准入条件、资金路径、退款和结算规则。
- 平台服务费的计费对象、计费时点、合同依据和开票安排。
- 用户协议、平台规则、隐私政策、交易合同及投诉处理机制。

**验收条件：**形成书面主体关系图、合同关系图和资金流图；由法律、税务及支付专业方对适用事项进行核验。支付机构接口可用不等于业务模式已合规。

## 3. 分阶段实施

### 阶段 A：市场与供给验证

工作内容：
- 确定候选城市、目标用户和首批服务品类。
- 访谈业主、施工人员、个体经营者和施工企业。
- 收集真实需求样本、常见报价方式、施工范围、验收争议和售后问题。
- 招募并核验首批服务商，建立服务区域、技能、服务能力档案。
- 以人工运营方式撮合少量真实订单，记录全链路数据。

交付物：
- 首发城市与品类选择报告。
- 用户访谈和服务商访谈记录。
- 服务商准入清单及审核规则。
- 真实需求与报价样本。
- 人工撮合实验数据和主要问题清单。

验收标准：
- 有可联系、可核验且愿意承接订单的供给方。
- 有真实需求方愿意发布需求并接受报价。
- 能观察到需求到报价、报价到签约、签约到完工的实际转化。
- 能识别获客、履约、投诉和售后成本的主要来源。

### 阶段 B：交易基础 MVP

产品范围：
- 手机号/账户注册与登录。
- 个人资料及服务商档案。
- 服务商主体资料提交、审核和状态管理。
- 住宅需求发布、编辑、撤回和平台审核。
- 需求列表、详情、区域和品类筛选。
- 服务商查看可参与需求。
- 结构化报价、报价版本、报价有效期。
- 需求方选择服务商及交易确认。
- 合同信息录入、文件上传、版本和双方确认记录。
- 站内消息或可靠通知能力。
- 运营后台的用户、需求、服务商、报价和交易管理。

暂不纳入：
- 全国多城市复杂调度。
- 自动竞价算法和复杂推荐模型。
- 商业工程全流程管理。
- 自建钱包、可提现余额或平台资金池。
- 复杂供应链商城和仓储物流。
- 微服务拆分及多活部署。

验收标准：
- 需求发布、审核、报价、选择和交易确认可完整操作。
- 关键操作均有操作者、时间和结果记录。
- 未通过审核或被限制的服务商不能参与受限交易。
- 报价变更产生新版本，不覆盖已确认版本。
- 交易关键状态只能通过服务端规则迁移，客户端不能任意指定状态。

### 阶段 C：履约、验收与售后

产品范围：
- 预约与开工确认。
- 施工日志、现场图片和关键节点记录。
- 隐蔽工程等关键环节的留证要求。
- 施工范围及费用变更申请、双方确认。
- 完工申请、验收清单、验收结果和整改记录。
- 取消、超时、争议、投诉和售后工单。
- 评价及评价申诉处理。
- 订单状态与合同状态、履约状态、支付状态分别管理。

验收标准：
- 每项变更能够追溯提出方、内容、金额影响和双方确认。
- 验收不通过可进入整改或争议处理，不得直接伪装为完成。
- 施工证据具备关联订单、上传者、时间和访问权限控制。
- 订单关闭不自动推断资金已结算。
- 投诉和争议有受理、处理、升级及关闭记录。

### 阶段 D：合规支付与财务对账

前置条件：Gate 0 的主体、合同、资金路径和支付产品核验已通过。

产品范围：
- 支付机构商户进件及状态同步（按合作方能力）。
- 订单支付请求和支付结果记录。
- 支付回调验签、幂等处理和异常补偿。
- 退款申请、退款结果和部分退款记录。
- 外部结算流水导入或查询。
- 订单、支付、退款、结算和平台服务费的对账。
- 对账差异处理及审计日志。

明确禁止：
- 未经许可自行归集、保管或划转交易资金。
- 自建可提现用户余额并将其当作真实资金账户。
- 以内部账本记账替代银行或持牌支付机构的实际结算。
- 未经支付机构确认就自行设计任意分账路径。

验收标准：
- 支付成功、失败、重复回调、超时、退款和部分退款均有测试用例。
- 每笔平台侧支付记录能够关联合作机构交易标识。
- 每笔结算记录能够追溯收款主体、金额、时间及外部流水。
- 差异账目可识别、可处理、不可静默覆盖。
- 业务订单状态与资金状态独立维护。

### 阶段 E：小范围试运营

工作内容：
- 限定城市、服务品类和服务商范围。
- 设置人工运营审核和客服支持。
- 持续观察交易转化、履约质量、投诉和退款。
- 对比不同获客渠道、服务费方案和服务商参与意愿。
- 每周复盘异常订单及服务质量问题。

试运营指标：
- 有效需求数及有效需求占比。
- 平均每条需求获得的有效报价数。
- 需求到报价转化率。
- 报价到签约转化率。
- 签约到完工率。
- 按时履约率、验收通过率、返工率。
- 取消率、退款率、投诉率和纠纷处理时长。
- 单笔订单平台实际收入、获客成本和可变运营成本。
- 服务商活跃率及重复接单率。

不预设虚构的行业基准值。指标目标应在获得首批真实样本后确定，并注明样本量和统计口径。

## 4. MVP 验收总清单

| 领域 | 必须通过的验收 |
|---|---|
| 身份与权限 | 个人、服务商、组织及运营角色权限隔离 |
| 需求 | 发布、审核、撤回、状态记录 |
| 服务商 | 资料审核、准入限制、停用机制 |
| 报价 | 结构化报价、版本、有效期、选择记录 |
| 合同 | 签约主体、服务范围、金额、版本和确认凭证 |
| 履约 | 预约、施工日志、关键证据和变更确认 |
| 验收 | 验收、整改、争议和关闭 |
| 售后 | 投诉、退款协作、质保和评价处理 |
| 支付 | 合作机构真实交易、退款、结算和对账 |
| 运营 | 用户/服务商审核、订单监管、审计和数据报表 |
| 安全 | 敏感信息保护、访问控制、文件权限、备份恢复 |
| 经营 | 能计算转化率、履约质量和单笔贡献经济 |

## 5. 建议研发顺序

1. 领域边界与状态机评审。
2. 用户、组织、服务商及权限。
3. 需求与服务品类。
4. 报价和撮合。
5. 合同与文件。
6. 施工履约、变更和验收。
7. 售后与运营后台。
8. 支付机构方案核验及支付适配。
9. 对账、监控、安全和试运营报表。

支付合规核验属于前置工作，不应等到研发末期才启动；上述研发顺序仅表示支付接口的实现依赖业务关系和合作机构方案。

## 6. 质量与发布门槛

上线前至少完成：
- 关键业务流程端到端测试。
- 角色越权和组织数据隔离测试。
- 幂等、并发报价、重复提交和重复回调测试。
- 订单、合同、支付、退款和结算状态一致性测试。
- 文件上传、下载、访问授权和恶意文件防护测试。
- 数据备份与恢复演练。
- 监控告警、日志审计和故障处理预案。
- 用户协议、平台规则、隐私政策和客服流程审核。
- 支付机构生产环境联调及真实结算核验。

## 7. 暂不承诺的事项

- 不承诺固定开发周期或固定团队规模，需在需求范围和资源确认后估算。
- 不将100万DAU直接作为首期容量验收标准。
- 不在缺乏城市样本时给出确定的转化率、客单价或盈利预测。
- 不将商业工程、材料交易和复杂企业SaaS列入住宅MVP的强制上线范围。
- 不将支付机构接入等同于平台整体合规完成。

## 8. 下一步需要形成的项目决策

| 决策项 | 当前建议 | 状态 |
|---|---|---|
| 首期经营模式 | 第三方撮合市场 | 待确认 |
| 首发城市 | 通过供需调研选择 | 待验证 |
| 首批服务品类 | 住宅安装、维修或局部改造中择优 | 待确认 |
| 首期供给 | 经审核的个人经营者及施工企业 | 待确认 |
| 交易履约 | 先人工运营辅助，逐步产品化 | 建议 |
| 支付方案 | 银行/持牌支付机构适配 | 待专业确认 |
| 商业工程 | MVP后独立迭代 | 建议 |
